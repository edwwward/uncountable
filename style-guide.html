Uncountable 3.0 — Style Guide

Core Palette

Raw brand hues — fixed values that do not flip between themes. Reference by variable name, never by hex. Human names match DESIGN.md so both docs speak the same language.

Suite accents

One accent per product suite, used for the suite dot in the Solutions nav panel and suite-scoped highlights. Each suite reuses a Core Palette color rather than introducing a new one — Plum is the only addition, for Product Lifecycle. R&D is Emerald, Quality is Azure 700, and Innovation & PM is Amber.

Tints

Light washes for illustration fills and the mint/sky resource-card headers. Backgrounds and graphics only — never text.

Neutrals

The gray ramp flips with the theme: solid cool grays in light, white-alpha overlays in dark. Values below are live-resolved for the current theme.

Semantic Tokens

Flip between light and dark via [data-theme]. Always prefer these over raw brand colors for text and surfaces. Values below are live-resolved for the current theme.

Theming

The site ships one theme. style.css declares a single, already-dark token set on :root, and [data-theme="light"] is a scoped override applied to individual elements so product screenshots read light on the dark page. It is not a page-level light mode, and script.js contains no theme logic. This guide is the one documented exception.

The shipped model

  • Dark is the root. style.css defines 84 tokens on :root, already resolved to their dark values, with color-scheme: dark. There is no separate dark block to opt into.
  • Light is an island, not a mode. [data-theme="light"] is the only theme selector in the file. It re-declares 30 of those 84 tokens and sets color-scheme: light, so native controls and scrollbars inside the island follow.
  • Islands nest by attribute. It is an ordinary attribute selector, so it applies to any element and cascades to that element's whole subtree. The nearest ancestor carrying the attribute wins for the 30 tokens it re-declares; every other token keeps inheriting from :root.
  • Nesting is one-way. There is no [data-theme="dark"] rule in style.css, so a subtree cannot be returned to dark by attribute. Scope the island tighter instead of trying to reverse it.
  • The page attribute is documentation, not styling. index.html and customers.html both open with <html data-theme="dark">. It records intent and matches no rule.
  • This page runs the same model, from the same file. The guide <link>s style.css and declares no tokens of its own, so :root here is the shipped dark set and the header toggle just moves data-theme="light" on and off <body> — exercising the real island rule rather than a copy of it. Until this revision the guide forked all 68 tokens into an inverted block of its own, which is how it came to publish a --space-* scale that existed nowhere.

Where islands are used

Ten islands ship. In index.html: the hero email capture (.hero-cta), the dashboard preview (.dash-preview), the Bodie app frame (.bodie-preview), and six Solutions card panels (.viz). In customers.html: the product tour frame (.tour-frame). Nine are product surfaces or screenshot stand-ins; the tenth, .hero-cta, is a live email-capture form that the island renders as a white field on the dark hero. No other element carries data-theme="light".

Token traps

Seven places where the obvious token is the wrong one. Each is checked against style.css, not inferred from the model.

  • --brand-ink and --brand-primary diverge only inside an island. Both are Azure on the page, so they look interchangeable. In an island --brand-ink becomes Midnight and --brand-primary does not move. Pick by intent: --brand-ink for anything that should re-ink with its surface.
  • --u-ink and --u-gray-700 diverge only outside one. Both are #3C4554 inside an island. On the page --u-gray-700 is #C6D1E1 and --u-ink never moves. For text, use --text-body.
  • --grad-dark is never remapped. Its stops are #061156, #020D4C and #01081f, measuring 1.13, 1.08 and 1.02 against the page — the last stop is all but the page itself. Always pair the band with a 1px --border-subtle hairline, or use flat --surface-dark instead.
  • An island flips tokens, not literals. .bodie-preview carries the attribute but paints itself #0A1238 and its chat column in rgba(255,255,255,…); only .bodie-list, which reads var(--surface-card), turns white. Hard-coded values ignore the scope entirely.
  • Tokens with no light override still resolve. --surface-dark, --surface-nav, --surface-nav-scrolled and all four gradients keep their dark values inside an island. Nothing errors — it renders dark on white.
  • --surface-card-ring gets whiter in the island. rgba(255,255,255,0.06) → rgba(255,255,255,0.35). It is a halo around a white card floating on the dark page, not a ring for a light page, so on a genuinely light ground it vanishes.
  • Undefined tokens fail silently. --surface-1, --u-gray-500, --u-gray-800, --u-gray-900 and --u-tint-green appear nowhere in style.css; var() on any of them drops the property with no warning. The ramp has seven steps — 50, 100, 200, 300, 400, 600, 700, with no 500, 800 or 900 — the sunken surface is --u-surface-1, not --surface-1, and the shipped tints are --u-tint-cyan, --u-tint-cyan-2 and --u-tint-green-2. There is no unsuffixed --u-tint-green.

Gradients

Four gradients, and no fifth — everything else in the system is a flat fill, with no textures or pattern overlays. On the shipped site none of the four flip with the theme: style.css declares one value each under “raw, do not flip”, and the light island overrides no gradient. The light --grad-hero below is this page's own light-mode value and has no counterpart in the site CSS.

  • --grad-dark needs a hairline. Its darkest stop #01081f is 1.02:1 against --surface-page — without a 1px --border-subtle border the band has no visible edge. Enforced on the Bodie band, footer CTA and tour frame.
  • --grad-cyan is decorative only. White on it measures 1.98:1 at the cyan stop and 4.99:1 at the blue stop, so it fails AA across most of its length. Fine behind avatar initials; never behind informational text. On flat cyan, use Midnight #020D4C (9.10:1).
  • --grad-mint is the only sanctioned home for the green tint. --u-tint-green-2 is never a standalone fill.

There are no spacing variables in this system. Earlier revisions of this page published a --space-1…--space-9 scale; it was never real. Nothing declares those names, so padding: var(--space-5) resolves to nothing. What ships is two layout formulas and a 4px grid applied as raw values.

The 4px grid

Every fixed gap, pad and inset is a multiple of 4. These are a convention the values follow, not variables you can reference — write the number.

If a new value is not a multiple of 4, it is a mistake or it needs a stated reason. Anything that must scale with the viewport uses one of the two formulas above rather than a new fixed step.

Motion

--ease-out: cubic-bezier(0.22, 1, 0.36, 1) is the system curve and covers everything except one case. Durations are split by what they animate, not by how big the element is.

  • --dur-fast, 140ms. Transform and press feedback.
  • --dur-base, 220ms. Color, background, border.
  • --dur-reveal, 600ms. Scroll-triggered section entrances — fired once by IntersectionObserver at 20% visibility, never scroll-linked, never replayed.
  • --dur-slide, 620ms + --ease-slide. The voices carousel track only. --ease-slide is a gentler ease-out (cubic-bezier(0.22, 0.61, 0.36, 1)) because the system curve arrives too abruptly across a 600px translate. It is the one sanctioned second curve — do not reach for it elsewhere.
  • Entrances rise 18px and fade in. Staggered groups offset each child by 100–120ms. The testimonial panel is not staggered; it cross-fades as a unit.
  • Animate transform and opacity by default. Three shipped components animate a layout property because no transform equivalent exists: the nav mega-panel's max-height, the testimonial progress bar's width, and the voices dot's width. Adding a fourth needs a reason.
  • One infinite loop exists — the customer logo marquee, 36s linear, paused on hover and disabled under reduced motion. Nothing else loops.
  • Reduced motion collapses every duration to 0.001ms globally. Note it zeroes duration only: transition-delay survives, so stagger offsets still apply. JS-driven motion is not covered at all — gate it on matchMedia('(prefers-reduced-motion: reduce)') and jump straight to the end state.

Iconography

Inline Lucide SVG. No icon font is loaded anywhere on the site — the only webfonts are Poppins and IBM Plex Mono. Every glyph is drawn on a 0 0 24 24 viewBox with fill="none", stroke="currentColor" and rounded caps and joins, sized in px by the component that holds it and colored by the text color it inherits. One asset serves both themes.

Markup

Paste the glyph body inside this wrapper:

<svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.75" stroke-linecap="round" stroke-linejoin="round">

Only two things on that element are ever yours to set. stroke-width is 1.75 unless the glyph qualifies for 2 under Stroke weight below, and width/height may be added when the component has no CSS rule to size the SVG — three shipped icons are sized that way. Nothing else belongs there: no class for color, no stroke other than currentColor, no fill other than none.

Sizes in use

There is no icon size token. Each component sizes its own SVG, either through a CSS rule on the parent or through inline width/height attributes. Reach for the nearest shipped size instead of introducing a new one. An SVG given neither renders at 300×150 — the CSS default for a replaced element with no intrinsic size, not a value this system chose.

Color

Icons carry no color of their own; the parent sets it and currentColor follows. The shipped assignments:

  • --u-blue-600. Nav mega-menu icons and industry pills. Both live inside .nav-panel, which is --surface-card with no light island around it — so on the shipped pages this is Azure on a dark panel, not a light one: 3.65:1 on the --u-surface-1 icon tile, 3.45:1 on the panel itself. Both clear the 3:1 bar for graphical objects with very little headroom, so do not darken those surfaces further. The same token is 4.99:1 on white if you need it on a light island.
  • --u-cyan. Accent icons inside the dark Bodie band (.bodie-prompt, .bodie-feature) — 8.5:1 or better against every stop of --grad-dark. Rail icons in that same band drop to rgba(255,255,255,0.4) (3.64:1 composited) because they read as inactive chrome, not accent.
  • --text-link. Inline “go” affordances — the recommendation header, and the case-study read arrow, which inherits from .case-read rather than setting its own color.
  • --text-strong. Neutral chrome — the Solutions panel footer (.nav-suites-foot svg), the one icon whose color is set separately from the muted text beside it.
  • --u-navy. Icons sitting on a Sky Cyan fill: the tour play triangle and the Bodie send arrow, both 9.10:1. Contrast comes from the fill beneath, so the icon takes the darkest token available.

Stroke weight

Two weights ship. 1.75 is the default and covers 38 of the 43 icons on index.html and customers.html. The five at 2 are bare geometric marks rather than pictographs — the tour play triangle and four arrows — where 1.75 goes weedy against a large fill or beside 14px type. Pictographs stay at 1.75; use 2 only for an arrow or a triangle. If you grep and find a third value, stroke-width="3" appears twice: both are polylines inside the two chart SVGs, which are drawings, not icons.

Rules

  • The No-Emoji Rule. Emoji are never UI iconography — not as a stand-in for a missing icon, not as flair in a toggle, badge, or status chip. An emoji renders in whatever font the OS ships, so its color, weight, and style all sit outside the system, and it obeys none of the sizing, stroke, or color-token discipline above. Use a Lucide glyph instead. Nothing in the shipped source breaks this today; keep it that way.
  • Unicode arrows are the one exception. &larr; &rarr; &uarr; set as type: the announcement link, the carousel controls (18px glyph inside a 64px .icon-btn-lg), the .flow-arrow connectors, and the ↑ in .statblock-accent at clamp(40px, 6vw, 76px). Those are Poppins characters, not icons — they scale with type and take no stroke attributes. The exception covers arrows and nothing else.
  • Lucide only. One library, pulled from lucide.dev. It is also what the Academy app ships (lucide-react), so both surfaces draw from the same set. Note the conflict with DESIGN.md: it names Material Symbols Rounded as the icon family and permits Lucide only under a “non-brand exception” scoped to tools needing two or three glyphs. The marketing pages ship 43. No Material Symbols font is loaded on any page, so Lucide is what is actually shipped — but the exception no longer describes the situation, and DESIGN.md and this page should be reconciled rather than left to disagree.
  • currentColor, always. A hardcoded stroke="#046CDE" survives one theme and breaks in the other. Set color on the parent so the same glyph works on white and on --grad-dark.
  • Stroked, not filled. Every icon on the site is fill="none". The only filled marks are the six data points inside the two chart SVGs and the 9px .suite-dot, which is a CSS element rather than an icon.
  • Size the parent, never the path. Width and height belong on the SVG element via the component's CSS rule or inline attributes. Do not scale a glyph by editing its path data.
  • Pull fresh path data. A few shipped glyphs are variants whose path data no longer matches the current Lucide release. Copy from lucide.dev, not from a neighboring element on the page.

Usage Rules

The rules that keep the palette accessible. Every ratio below is computed, not eyeballed — do the same before shipping a new pairing.

  • The Amber Rule. Amber is dark-surface only: 1.8:1 on white fails even the large-text bar. Chart thresholds, control-band markers, dark badges — never type on a light surface.
  • The Emerald rule. Emerald is for icons, fills, and graphical marks (≥3:1 non-text bar). The moment it renders as a character glyph, switch to a darkened text variant.
  • Azure has no headroom as text. 4.99:1 on white passes AA with almost nothing to spare — keep Azure text on white or lighter surfaces only, and never shrink it below 14px.
  • surface-dark is lifted. Dark cards use #0C1C63, not raw Midnight — Midnight is 1.08:1 against the dark page and reads as invisible.
  • 500 is bold. Only Poppins 400/500 are loaded. A heavier weight will silently render as faux-bold or fall back — cap everything at 500.
  • No colored accent stripes. Cards and callouts never get a colored side or top border. Use a tag, a tinted ground, or nothing.

Logo

White wordmark on dark chrome (nav, footer — rendered at 26px height). Navy monogram on light surfaces and as the favicon. Never recolor, never place the navy mark on a dark ground.

Buttons

CTA is Azure and darkens to --u-blue-700 on hover. Accent (Sky Cyan with Midnight text) is reserved for dark bands. Color/border fade over 220ms (--dur-base); any transform (e.g. a hover lift) runs at 140ms (--dur-fast) — the same split as every other hover state on the site.

Interaction States

Hover, press, focus, disabled. Every value below is read off style.css — that file is the contract. Where the Figma motion page disagrees, the shipped rule is documented and the gap is named.

Hover

  • Buttons lift 1px. .btn:hover is translateY(-1px) plus a text-decoration: none reset, and nothing more — the shadow never steps. Figma's Motion page opens by claiming a 2px hover lift; nothing on the site moves 2px.
  • Cards lift 4px. .case-card:hover is translateY(-4px) plus --shadow-xl. It is the only card with a hover transform — .voices-card and .testi-quote-card also move, but off state classes, never off the pointer. .res-card carries cursor: pointer and no hover rule at all, and .sol-card has neither.
  • Solid fills swap, Accent inverts. CTA darkens to --u-blue-700 through --brand-primary-hover. Primary lands on the same colour but writes it as a literal #0356B4, twice — the one hover in the file that ignores the palette's own “reference by variable name, never by hex” rule. Accent goes the other way and lightens to --u-tint-cyan; its label is Midnight, so that pairing widens from 9.10:1 to 12.31:1 instead of compressing.
  • Outlines fill, they do not thicken. .btn-outline:hover takes --u-surface-1; .btn-outline-light:hover takes rgba(255,255,255,0.12) and a #fff border. Hover moves border-color only — the 1.5px border is what gives solid and outline an identical footprint, and thickening it on hover would shove the row sideways.
  • Icon buttons invert, never lift. .icon-btn-outline:hover fills with --brand-ink, sets #fff glyph and a matching border. There is no transform: .icon-btn's transition list is background and border-color only. color is absent, so the glyph snaps while the fill takes 220ms — for that window on the way out the arrow is --text-strong sitting on a fill that has not finished clearing, and it disappears. Shipped as-is; add color to the transition list if you fix it.
  • The tour play button scales. .tour-play:hover .tour-play-btn is scale(1.06) — the one control that grows rather than lifts: it sits centered on the video frame, where a lift has no edge to read against.
  • Rows and links tint their ground. Nav mega-items and suite links take --u-surface-2; the suite link also goes --text-link. Industry pills take --u-blue-600 for border and text over that same ground. Marquee logos are the one link that recolors instead of tinting — .cust-logo:hover goes --text-link with no underline. Bare links fall back to a:hover, an underline.
  • Transform 140ms, color 220ms. That split holds on .btn. Two hover transforms break it and run at --dur-base: .case-card and .tour-play-btn. Transforms that are not hover run on their own budgets — --dur-reveal for entrances, --dur-slide for the carousel, and one unbudgeted 0.35s literal on the testimonial cross-fade. A third hover exception needs a reason.
  • Gate hover behind a pointer query only when it withholds something. The logo marquee's hover-to-pause sits inside @media (hover: hover) and (pointer: fine) — the only such gate in the file — because a touch device would otherwise never resume. Everything else here is decorative and stays ungated.

Press

  • Press is scale(0.97). .btn:active, at --dur-fast. It matches the Figma spec exactly.
  • Press replaces the lift, it does not stack. Both states write transform, and :active is declared after :hover at equal specificity, so a held button sits flat and shrunk rather than lifted and shrunk. Keep that source order in any copy of this pattern.
  • Nothing else has an :active rule. .btn:active is the only one in the file. Icon buttons, case cards, the play button and the carousel dots do not respond to being held. Adding press feedback means adding it to the whole control family, not to one component.

Focus

  • No custom focus ring ships. There is no :focus or :focus-visible rule anywhere in style.css; every control shows the browser default. The Core Palette above still labels --u-blue-400 the focus-ring colour — that ring was specified and never built. Do not replace the default with something quieter: match it or beat it, and --u-blue-400 is the value waiting for whoever does.
  • Hover styling is not focus styling. .icon-btn-outline:hover fires on pointer only. A keyboard user reaching that button gets the default ring and no fill, which is why the ring has to survive.
  • Two elements suppress the outline. .searchfield-input and .voices-viewport both set outline: none. They are the only two. The search field's 8px --surface-card-ring is static and does not stand in for a focus ring.
  • The voices viewport is the live gap. It is tabindex="0", it owns the Arrow Left / Arrow Right handler, and its outline is off — a keyboard user can drive the carousel with no visible sign of where focus sits. Fix it before copying the pattern.

Disabled

  • Disabled is opacity: 0.4 plus cursor: not-allowed. .icon-btn:disabled. No color or border swap — one opacity carries the state in both themes.
  • Kill the hover on the disabled element. .icon-btn-outline:disabled:hover restores transparent, --text-strong, --border-default. CSS still matches :hover on a disabled button, so without that line a dead arrow fills with --brand-ink at 40% and reads as live.
  • Set it as a property, not a class. The voices carousel sets the button's disabled property at each end of the range, so the state reaches assistive tech for free. A visual-only is-disabled class does not.
  • .btn has no disabled state. Nothing styles .btn:disabled, and most buttons on the site are anchors. If one is needed, mirror the icon-button recipe rather than inventing a third treatment.

Across all four

  • The transition lives on the base class. .btn, .icon-btn, .case-card and .tour-play-btn declare it; the pseudo-class only sets the end value. That is what makes the state ease back out as well as in.
  • Reduced motion keeps the state and drops the tween. The global rule zeroes transition-duration, so a hover still lifts and a press still shrinks — they just arrive instantly. Never branch on reduced motion to remove the transform; the state has to stay readable.

Focus ring

Tab into either demo above. Nothing in style.css defines a focus style today — this is the specification, not a description of shipped code.

  • The ring is 3px --u-blue-400 (#2E86E8) with the field's 1.5px border switching to the same color. It clears the 3:1 non-text bar on both grounds — 5.26:1 against --surface-page on dark, 3.69:1 against white. Blue-400 is the focus color and has no other job in the system — it is otherwise a chart and illustration accent.
  • Focus outranks error. A field in the error state still takes the blue border and ring when focused; the message below is what keeps carrying the error. Scope the focus rule so it wins the cascade against the error rule rather than losing to it on specificity.
  • Composite controls take the ring on the shell. The search field puts it on .searchfield via :focus-within, not on the borderless input inside — a ring drawn around a transparent input floating in a card reads as a misprint.
  • Nothing ships today. style.css contains no :focus-visible rule at all, and two elements clear the native indicator with no replacement: .searchfield-input, and .voices-viewport, which is tabindex="0" and therefore genuinely reachable. A keyboard user tabbing to the hero email field currently gets no visible target. Fix the removal before adding the ring anywhere else.

Rules

  • 1.5px border, 6px radius. Same border weight as .btn and the same --radius-control, so a field and its button have an identical footprint. The search field is the documented exception: its shell is a card at --radius-lg.
  • Bind label and value to --text-strong. Shipped .searchfield-input still hard-codes --u-navy. It survives only because the hero wraps the field in a data-theme="light" island — the same field on the dark page measures 1.05:1 against --surface-card and disappears.
  • Placeholder is not a label. Placeholder is --text-muted and vanishes the moment someone types. Every field carries a visible <label>, or an aria-label where the layout genuinely has no room — the search field is the only one that qualifies.
  • Errors turn the border --u-orange and add a message below. Never carry the error in color alone: Amber is 1.84:1 against white, under the 3:1 bar a state indicator has to clear, so on a light island the border shift alone does not register as a signal — it swaps one low-contrast edge for another. The message text is --text-body — the palette has no error text token, and Amber type fails on light.
  • Native controls follow color-scheme. Both theme scopes in style.css declare it, so date pickers, select menus, autofill chrome, and scrollbars match the surface without extra styling. A new theme scope that omits it will render light OS chrome on a dark card.

Section Recipes

Every page is a stack of full-bleed bands. A band owns its background and its vertical padding; a 1280px container inside it owns the horizontal edge. The content shape barely varies — eyebrow, left-aligned display headline, then the payload.

The frame

  • One container, 1280px. .container-max is max-width:1280px; margin:0 auto; padding:0 clamp(20px,3vw,40px). The nav bar, the mega-panel and the footer inner all repeat those same three declarations, so the page edge never shifts between chrome and content.
  • The gutter is clamp(20px,3vw,40px). 20px on phones, 40px from roughly 1333px up. It is the only horizontal inset in the system — no section invents its own.
  • Standard rhythm is clamp(56px,8vw,112px), top and bottom, set on the <section> rather than the inner wrapper so the background fills the whole band. Solutions, Stats, Testimonials, Resources, Voices, Tour and Case Studies all use it. Deviations are deliberate, few, and always smaller: hero clamp(40px,5.5vw,88px), Bodie clamp(48px,7vw,96px), footer CTA clamp(56px,7vw,104px), logo marquee a flat 40px 0 48px.
  • The head block is near-fixed. .eyebrow, the display headline 14px below it, then 40px to the content. The head row — one shared rule for .solutions-head, .resources-head and .stats-head — is flex with align-items:flex-end and justify-content:space-between at 24px gap, so a trailing button or arrow pair sits flush with the bottom of the headline instead of floating above the cards. Testimonials is the exception: no head row at all, and 48px under the headline.
  • Carousel tracks break the container on purpose. .sol-track and .res-track run edge to edge and carry the gutter as their own padding:4px clamp(20px,3vw,40px) 20px. The first card lines up with the container, the rest bleed off the right edge to signal there is more. 22px gap, scroll-snap-type:x mandatory.
  • New sections use the class. index.html predates .container-max and never references it; instead seven rules of its own re-declare those three properties — .hero-inner, .customers-mask, the shared .solutions-head/.resources-head/.stats-head, .stats-feature, .stats-row, .testimonials and .footer-links-inner. customers.html uses the class. Build the second way.

Voice & Content

Precise, confident, technical but human. The reader is you; the company is we. We sell momentum, not features. Casing is enforced in CSS wherever it can be — type strings in sentence case and let text-transform uppercase them.

Rules

  • Headlines are typed in sentence case. Including the ones that render in caps: every --text-display-lg section title carries text-transform:uppercase, so “Proof, at production scale” ships as typed and renders as PROOF, AT PRODUCTION SCALE. --text-display-xl — hero and footer CTA — has no transform and renders exactly as written.
  • Periods inside short headlines. Two- and three-beat headlines take terminal periods for cadence: “Less guessing. More discovery.” and “Run. Capture. Predict.” A single-clause headline takes none — the hero H1 is “Reach the answer in fewer experiments” with no period.
  • CTAs are verb-first sentence case. The shipped .btn set is Request a demo, Book a demo, Talk to sales, See the platform, See all case studies — two to four words, no terminal period, never Title Case. Inline link CTAs follow the same rule: Read the announcement →, Read case study. Those two carry their arrow differently — .announce-link uses a typographic → inside the string, .case-read appends an inline Lucide arrow — so match the component you are writing into rather than picking one. .btn sets white-space:nowrap, so a long label widens the button rather than wrapping.
  • Eyebrows are typed in sentence case too. .eyebrow supplies text-transform:uppercase and --tracking-eyebrow (0.14em), so write “By the numbers”, not “BY THE NUMBERS” — the string stays legible in markup, in search, and in a CMS field. The same holds for every other uppercase-by-CSS label: .dash-head, .voices-company, .footer-col-title, .tour-play-label. Type caps only where the class carries no transform — .res-kicker (PLAYBOOK, CASE STUDY), .testi-tab-label, .viz-label — or where the string is an acronym or a wordmark, which keep their own casing everywhere (ELN, QMS, BEHR, SOPREMA).
  • An eyebrow names its container and nothing else. Section eyebrows: Platform, By the numbers, Our customers, Resources, Customers, In their words, The platform, Case studies. The .eyebrow-muted variant does the same job one level down, naming a single card — Design of Experiments, ML Recommendations, Analytics. Either level: no item counts, no parentheticals.
  • Stats read figure first, label beneath. Two shipped patterns, and a block commits to one. Standalone: .statblock-value (Poppins 500, -0.04em) over a sentence-case .statblock-label with no terminal period — 40% above Fewer experiments. Continuation: .cust-proof-value over a lowercase .cust-proof-label that finishes the phrase — 30% above less time spent reconciling data. Only a stat that expands into a full sentence takes a period — “Increase in experiment throughput in the first year.”
  • Numbers stay compact. % never “percent”; comma-group at four digits (1,000+); trailing + for open-ended counts (12M+, 250+); ~ and > for approximations (~75%, >50%); abbreviated units take no period (6 mo, 3 min).
  • Math glyphs, not keyboard stand-ins. −40% uses U+2212 MINUS SIGN, not a hyphen, and 3× uses U+00D7 MULTIPLICATION SIGN, not a lowercase x. Both are cut to the width and height the digits expect; the keyboard substitutes sit too small and too low beside a --text-display-lg figure.
  • Mono is for tabular data and readout labels — never for the figure itself. --font-mono carries the experiment matrix (.dash-grid — A-01, EP-2, 12, 120, 88), the label above a readout (.dash-rec-label), viz labels and rows, and the carousel counter (.voices-counter — 01 / 04, zero-padded to two digits). Every headline figure stays in Poppins, the dashboard’s own 96.4 and +5.4 included: .dash-rec-value is --font-display and .dash-rec-delta is --font-body.
  • Banned vocabulary. No leverage, enable, optimize, advanced algorithms, or data-driven. Name the action and the result instead. Two exceptions survive in house copy: OPTIMIZATION is a .viz-label naming a real optimization run — a technical noun on a chart is not the marketing verb — while “data-driven” in one resource blurb is plain debt. Fix the second; cite neither as precedent.
  • Quotes run verbatim. A customer quote keeps the customer’s words, banned vocabulary included — one shipped quote reads “has enabled our R&D organization…”. Trim with an ellipsis; never rewrite a quote into house voice.
  • No emoji, in copy or in UI. Every glyph is either type or an inline Lucide SVG with stroke="currentColor". Emoji render as a third, uncontrolled typeface — a different weight and style on every OS — and are not brand-approved marks.

What We Don’t Do

Patterns banned outright, because they read as generic template output rather than as Uncountable. If a layout only works with one of these, the layout is the problem — rework it. Every ban below was audited against style.css, index.html, customers.html and this guide; where a shipped exception exists it is named, not glossed.

  • No colored accent borders. No 2px, 3px or 4px accent stripe on the top, left, right or bottom edge of a card, callout, list item, alert, nav item or panel — not in brand colors, not in status colors, not in a gradient. Decorative, never meaningful, and instantly recognisable as filler. Use a tag, a tinted ground, a leading numeral, or nothing. This applies to every Uncountable page, not just this one: of the 23 width-bearing directional border declarations in the system, every single one is 1px, and the Academy bundle adds none wider.
  • No gradient text. background-clip: text over a gradient is decoration standing in for hierarchy. One solid color, with emphasis carried by size and tracking. Zero occurrences of background-clip, -webkit-background-clip or text-fill-color ship.
  • No glassmorphism as a default. Frosted panels used everywhere flatten the page and cost legibility. The sticky nav is the one sanctioned surface — backdrop-filter: saturate(180%) blur(14px) over --surface-nav, and the only backdrop-filtered surface in the stylesheet.
  • No identical card grids. Icon, heading, two lines of text, repeated nine times says nothing. Vary card size and density to match what each card actually holds. One bounded uniform grid per page is the cap — see the exception below.
  • No nested cards. A card inside a card inside a card reads as indecision. One level only: an inset panel may sit on a card, and nothing sits on the inset panel. Three shipped patterns use that level and no shipped panel goes deeper — see the exception below.
  • No decorative textures. The system’s surfaces are deliberately flat and clean — no noise overlays, no repeating patterns, no image fills behind type. Flat fills, or one of the four gradient tokens: --grad-hero, --grad-dark, --grad-cyan, --grad-mint. The stylesheet contains no background-image, no radial-gradient and no data: fill. Two raw gradients exist and neither is decoration: the .tour-scrim legibility wash over the tour poster, and the fade mask on the customer marquee.
  • No emoji. Not as a UI icon, not as a status marker, not as informal flair. An emoji renders in whatever font the OS ships — color, weight and style all outside the system’s control — so it carries none of the sizing and color-token discipline every other glyph on the page obeys. Use a Lucide icon as inline SVG with fill="none" and stroke="currentColor", or nothing. All 45 icons across the shipped pages are inline SVG, and no page in the system — marketing or Academy — contains a single pictographic codepoint.
  • No font weight above 500. It breaks the single constraint the whole type system is built on, and only the 400 and 500 Poppins faces are loaded — 600 silently faux-bolds or falls back. Emphasize with size, tracking and color instead. No font-weight above 500 is declared in style.css, either marketing page or this guide, and the five shipped <strong> elements are all reset to 500. The Academy app’s Tailwind bundle still carries a .font-bold (700) utility on two elements — the one outstanding violation in the system, not a licence for a second. See Typography.
  • No bounce or elastic easing. It reads as playful; this is a platform for scientists. Ease-out only: hover lifts translateY(-1px), press is scale(0.97). The stylesheet defines exactly two custom curves, --ease-out and --ease-slide, and neither overshoots. See Motion.

Sanctioned exceptions

Four places the site does the adjacent-but-permitted thing. Stated precisely, so no ban above is read wider than it is.

  • 1px neutral hairlines are structure, not decoration. The stripe ban targets colored decorative accents. A 1px divider in --border-subtle separating columns or rows is correct and used throughout — .nav-suite, .cust-proof-item, .stats-row. Width and color are both load-bearing: 1px, and never a brand or status hue.
  • The sticky nav is the only glass surface. .nav alone. A second frosted panel anywhere is the failure, not a precedent.
  • One bounded uniform grid per page. The product band’s feature grid (.bodie-grid) is repeat(3, minmax(0,1fr)) holding six identical icon-heading-paragraph cells. That is the cap, not the license — every other group on the page varies deliberately: the resource carousel sizes cards at clamp(300px, 32vw, 380px), the testimonial panel splits 1.7fr / 1fr, and the stats row is auto-fit. A second uniform grid on the same page is the failure.
  • One inset panel is the one nesting level. Three patterns use it and stop there: a resource card’s gradient head (.res-card-head) inside the --surface-card card, the light-island data panel (.viz) inside a tinted solution card, and the recommendation card (.dash-rec-card) inside the hero dashboard preview. Anything deeper is banned.

Focus

style.css declares no :focus or :focus-visible rule, so every control falls back to the browser's default ring — engine-dependent and not guaranteed to clear 3:1 on #070C1F. Two rules strip it outright: .searchfield-input and .voices-viewport both set outline: none with no replacement, and the viewport is tabindex="0" with arrow-key handlers — a keyboard control with no visible focus at all. The ring below is the fix.

  • 3px --u-blue-400, offset 2px. #2E86E8 clears the 3:1 non-text bar on every dark ground and on white — 5.26:1 on --surface-page, 4.95:1 on --u-surface-1, 4.67:1 on --surface-card, 4.36:1 on --u-surface-2, 4.18:1 on --surface-dark, 4.66:1 on --grad-dark, 3.69:1 on a light island's white.
  • Two grounds need a darker ring. The blue ring is 2.52:1 on --u-tint-cyan — the announcement bar, which holds a real focusable link — and 2.87:1 on the light island's --u-surface-2 #DFE3EA. Swap to --u-navy there: 12.31:1 and 14.01:1.
  • The offset is load-bearing. The same ring is 1.35:1 against --u-blue-600 and 1.86:1 against --u-cyan. On the CTA and Accent buttons it must sit outside the fill, never on it. The offset does not rescue the announcement bar, where the fill and its surround are the same tint — that one needs the colour swap above.
  • Never remove it without a replacement. A change of background alone is not a focus indicator. If you take the outline off, the substitute has to be at least as visible and at least 3:1 against both the control and its surround.

Motion & system preferences

  • Reduced motion is a blanket. One rule collapses every animation-duration and transition-duration to 0.001ms !important. New components inherit it for free; nothing needs its own opt-in.
  • Loops and progress need an end state. The blanket alone would leave the customer marquee thrashing and the 15s testimonial bar frozen at zero width, so .cust-track sets animation: none and .testi-progress.is-running sets animation: none plus width: 100% — the finished state, not a blank one. Any new looping or progress animation needs the same pair of overrides.
  • Both scopes declare color-scheme. In style.css, :root is dark and [data-theme="light"] is light, so native scrollbars, form controls, and the text caret match the surface they sit on instead of the OS default.

Colour is never the only signal

  • Pair hue with shape and state. The open nav tab turns --text-link, rotates its chevron 180°, and flips aria-expanded. The active slider dot widens from 18px to 34px as well as changing fill, and sets aria-current. The active testimonial tab gains a progress track and sets aria-selected. The highlighted dashboard cell adds a tinted ground and weight 500.
  • The current page is the one exception. .nav-link-active marks it with --text-link and nothing else — no aria-current="page", no underline. Colour alone, and the only such case in the system.
  • There is no red in this palette. Nothing here encodes failure by hue, so say the outcome in words. This section's own tables print "Fails" rather than turning a row red.
